S1-1 · ACTIVATIONS EXIST FOR A REASON

Same data. Same optimizer. One activation function.

A model with no nonlinearity can only draw a straight decision boundary — so it can't separate two interleaved rings. Add a single ReLU hidden layer and it can wrap the boundary around the ring. Below: ~300 noisy points (inner ring = class 0, outer ring = class 1, not linearly separable), trained live in your browser, with the actual boundary curve traced on top of each panel as training progresses. Only the architecture changes between the two panels — everything else is identical.

Background: a neural network layer is really just z = Wx + b — a weighted sum, which is linear algebra. Feed that straight into a sigmoid and you get logistic regression: a classifier whose only trick is a straight decision line. An activation function like ReLU is a small nonlinear kink inserted after that sum — it's the one thing that lets a network bend space instead of just slicing it.
  • The equation printed under panel (a) — the literal straight line the model is restricted to, computed directly from its weights.
  • How panel (b)'s boundary starts almost flat, then progressively folds — each ReLU unit contributes one straight-line kink.
  • Final accuracy: panel (a) stuck near chance, panel (b) near-perfect.

S1-2 · DEPTH WITHOUT NONLINEARITY IS A LIE

Five linear layers. One effective layer.

Stacking linear layers with nothing in between them collapses algebraically to a single linear map — W₅(W₄(W₃(W₂(W₁x+b₁)+b₂)+b₃)+b₄)+b₅ is still just W·x + b. So a 5-layer linear network should be no stronger than a 1-layer one, and both should fail the ring task identically. Stack the exact same five layer sizes but put a ReLU between each of them, and suddenly the ring task is solvable. Same data, same depth, only the activations differ.

Background: "depth" is supposed to mean more expressive power — but only if something nonlinear happens between the layers. Multiply a chain of plain matrices together with no activation in between and you always get back a single matrix, no matter how many you chain. This module doesn't just claim that algebraically — it multiplies the five trained matrices together live, in your browser, and shows you the product.
  • Panels (a) and (b) should converge to the same line equation — five layers buys nothing over one when there's no nonlinearity between them.
  • The matrix-multiplication box at the bottom: the gap between the 5-layer network's real output and its collapsed single-matrix equivalent should be ~1e-15 — floating-point noise, not approximation.
  • Panel (c) is the identical size to (b). The only difference is four ReLUs — and it's the only one of the three that escapes the line.

S1-3 · EMBEDDINGS LEARN SIMILARITY FROM NOTHING BUT NEXT-TOKEN

Predict the next word. Get free geometry.

A tiny synthetic grammar with three word categories — animals (cat, dog, cow), fruits (apple, mango), verbs (eat, chase, see) — generates sentences like "cat chase dog" and "cow eat apple". Same-category words are interchangeable in the grammar, so they share next-token statistics. An embedding table trained on nothing but "predict the next token" — no labels, no similarity signal, no category ever supplied — is watched below as it self-organizes: same-category tokens get pulled toward the same region of embedding space purely as a side-effect of minimizing next-token loss.

Background: an embedding is a lookup table — each token gets a list of numbers, initialized randomly, and nothing in that setup knows what a "category" is. The only training signal is "predict the next token." If two tokens tend to be followed by the same things, the optimizer finds it cheaper to give them similar vectors, because similar vectors produce similar predictions. That distributional pressure is the entire mechanism behind word embeddings, from word2vec to the token embeddings inside a modern LLM.
  • Dots colored by category — color was never part of training, it's painted on afterward just so you can see the clusters.
  • The nearest-neighbor list: every arrow should point to a same-colored token.
  • The sample sentences at the bottom: flat, unlabeled text — that is the entirety of what the model ever saw.

    S1-4 · MEMORIZATION VS GENERALIZATION, AND DATA CLOSES THE GAP

    Same network. Same optimizer. Only the dataset size changes.

    A high-capacity network can drive train loss to ~0 on a tiny dataset by memorizing every point — including the mislabeled ones. That memorized noise doesn't generalize, so test accuracy stays low: a huge train/test gap. Below, the exact same over-parameterized network is trained on 20, 200, and 2000 points drawn from the same noisy, wavy-boundary classification task (~14% label noise, held-out test set shared across all three runs). Watch the decision boundary go from a contorted shape that traps every training point to a smooth curve that ignores individual noise — and watch the train/test gap shrink as the dataset grows.

    Background: a model with more parameters than training examples has enough freedom to just memorize the answer key — including any mistakes in it. That's overfitting: the loss looks great on training data, but the model hasn't learned the underlying pattern, it's stored a lookup table in disguise. The usual fix isn't a smarter model, it's more data — with enough examples, pure memorization stops being possible and the model is forced to find the real signal instead.
    • Panel N=20's boundary contorting around individual points, including the mislabeled ones.
    • Train accuracy near 100% at N=20 while test accuracy stays mediocre — that gap is overfitting, quantified.
    • By N=2000, train and test accuracy converge close to the noise ceiling — the gap chart at the bottom makes the trend explicit.
